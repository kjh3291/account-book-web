# Calendar Account Book (달력형 가계부)

달력 기반으로 수입/지출을 관리하고, 카테고리별 예산과 반복 지출까지 함께 관리할 수 있는 PWA 가계부입니다.  
웹 브라우저와 Android 앱 형태로 모두 사용할 수 있습니다.

---

# 주요 기능

## 기본 가계부 기능
- 달력 기반 수입 / 지출 관리
- 내역 추가 / 수정 / 삭제
- 메모 작성 가능
- 카테고리별 지출 관리
- 반복 지출 자동 등록

## 예산 관리
- 카테고리별 월 예산 설정 (월별 예산 목표)
- 예산 사용량 자동 계산
- 남은 예산 실시간 표시
- 사용 가능 잔액 자동 계산
- 실제 잔액을 항목별로 미리 나눠두는 잔액 예산 나누기 (월별 예산 목표 화면 상단 버튼으로 이동)

## 카테고리 관리
- 사용자 직접 카테고리 생성
- 카테고리 수정 및 삭제
- 많이 생성될 경우 “더보기” 지원
- 월별 예산 카테고리 자동 연동

## 설정 기능
- 다크 모드 지원
- 테마 색상 변경 (블랙+네온 그린 "몬스터" 테마 포함, 총 6종)
- 설정값 자동 저장(localStorage)
- 결제·입금 알림 켜기/끄기 (안드로이드 앱)

## 편의 기능
- 하단 고정 내비게이션 바 (홈 / 예산 / 추가 / 통계 / 설정)
- 내역 추가 시 금액 빠른 입력 버튼 (+1,000 / +5,000 / +10,000 / +50,000)
- 직전에 사용한 구분(수입·지출)/카테고리 자동 선택
- 결제·입금 예정 D-3/D-2/D-1 로컬 알림, 이번 달 사용 가능 금액 알림 (안드로이드 앱)

## Firebase 연동
- Google 로그인
- Firestore 데이터 저장
- 여러 기기 간 데이터 동기화

## PWA 지원
- 앱처럼 설치 가능
- 홈 화면 추가 지원
- 기본 오프라인 캐싱 지원

# Firebase 설정

Firebase 기능을 사용하려면 아래 설정이 필요합니다.

## 1. Authentication 설정
Firebase Console → Authentication → Sign-in method

```text
Google 로그인 활성화
```

## 2. Firestore 생성
Firebase Console → Firestore Database 생성

## 3. Firestore Rules 설정

```js
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      allow read, write: if request.auth != null
      && request.auth.uid == userId;
    }
  }
}
```

# Android 실행

Capacitor 기반 Android 앱 실행:

```bash
npm run build
npx cap sync android
npx cap open android
```

`npm run build`는 `index.html`/`script.js` 등 앱 런타임 파일만 `www/`(Capacitor의 `webDir`)로 복사합니다. `www/`는 매번 새로 생성되는 빌드 산출물이라 git에는 커밋하지 않습니다. `npm run cap:sync`로 두 명령을 한 번에 실행할 수도 있습니다.

Android Studio 실행 후:

```bash
Run ▶ app
```

- 일반 내역 수정 기능 추가
- 예산 수정 시 잔액 재계산 개선
- 사용 가능 잔액 계산 방식 수정
- 카테고리 관리 UI 개선
- 설정 메뉴 분리
- Firebase 로그인 구조 안정화
- Android 연동 구조 정리
- 모바일 UI 최적화
- **설정 > 데이터 백업에서 내보내기(JSON 저장) / 가져오기(JSON 복원) 기능 추가** (기기 변경, 데이터 유실 대비)
- **"잔액 예산 나누기" 화면 연결**: 화면과 로직은 이미 만들어져 있었지만 진입 버튼이 없어서 실제로는 열 수 없던 화면이었습니다. 월별 예산 목표 화면 상단에 이동 버튼을 추가해 정상적으로 쓸 수 있게 연결했습니다.
- **Google 로그인 오류 메시지 개선**: 실패 원인(팝업 차단, 승인되지 않은 도메인, file로 직접 열었을 때 등)을 구체적으로 알려주고, 팝업이 막히면 리디렉션 방식으로 자동 전환하도록 수정
- **capacitor.config.json 수정**: 존재하지 않는 `www` 폴더를 가리키던 `webDir`과, 기본 위치와 다른 곳에 있던 `account-book-android` 폴더 경로를 바로잡아 `npx cap sync android`가 정상 동작하도록 수정
- **서비스워커(PWA) 캐시 전략 수정**: 기존에는 캐시가 있으면 항상 캐시부터 보여줘서 코드를 고쳐도 이미 설치된 앱/PWA에 반영되지 않는 문제가 있었습니다. 온라인일 때는 항상 최신 파일을 받아오는 방식(network-first)으로 수정
- **블랙+네온 그린("몬스터") 테마 추가**
- **하단 고정 내비게이션 바 추가**: 홈/예산/통계/설정 화면 이동이 헷갈리던 문제를 개선. 기존 우측 하단 + 버튼은 하단 바의 "추가" 버튼으로 통합
- **내역 입력 편의성 개선**: 금액 빠른 입력 버튼, 직전 사용 구분/카테고리 자동 선택, 금액 입력창 자동 포커스
- **반복 항목 기반 로컬 알림 추가 (안드로이드 앱)**: 자동결제/용돈 입금 D-3·D-2·D-1 알림, 이번 달 사용 가능 금액 알림. 설정 화면에서 켜고 끌 수 있음

# 문제 해결 (트러블슈팅)

## Google 로그인이 안 될 때

아래 순서대로 확인해주세요.

1. **index.html을 더블클릭해서 파일로 직접 열지는 않았는지 확인**
   - `file://`로 열면 Google 로그인이 원천적으로 동작하지 않습니다 (브라우저 상단에 "file로 열림 (로그인 불가)"로 표시됩니다). 반드시 Live Server 등 `http://` 환경에서 실행해주세요.
2. **Firebase 콘솔 > Authentication > Settings > Authorized domains 확인**
   - 실제 접속 중인 주소(예: `localhost`, 배포한 도메인)가 이 목록에 있어야 합니다. `127.0.0.1`로 접속 중이라면 `localhost`로 접속하도록 바꿔보세요 (기본적으로 `localhost`만 승인되어 있는 경우가 많습니다).
3. **Android 앱에서 로그인이 안 된다면 `google-services.json` 확인**
   - `account-book-android/app/google-services.json`이 없어서 Android 네이티브 Google 로그인이 동작할 수 없는 상태였습니다. `/Users/jae_down/Desktop/account-book-pwa-ready/android/app/google-services.json`(같은 Firebase 프로젝트, 같은 패키지명 `com.gowoon.accountbook`으로 이미 등록되어 있던 파일)을 찾아 `account-book-android/app/`에 복사해 넣었습니다. `npx cap sync android` 후 Android Studio에서 다시 빌드하면 반영됩니다.
   - 다만 이 파일 안의 OAuth 클라이언트는 **특정 키스토어의 SHA-1 인증서 지문(`900992e5e00a270a9308f9bbb379fb80711e31a7`)**에 묶여 있습니다. 지금 빌드에 사용 중인 디버그/릴리즈 키스토어의 SHA-1이 이것과 다르면 여전히 로그인 시 `DEVELOPER_ERROR(10)` 오류가 날 수 있습니다. 그럴 경우 실제 사용 중인 키스토어의 SHA-1을 Firebase 콘솔 > 프로젝트 설정 > 해당 Android 앱에 추가로 등록하고 `google-services.json`을 다시 받아 교체해주세요.
4. **코드를 수정한 뒤 Android에 반영이 안 될 때**
   - `npm run build && npx cap sync android` 실행 후 Android Studio에서 다시 빌드해주세요. `capacitor.config.json`의 `webDir`은 `www`(빌드 산출물 폴더)를 가리킵니다 — Capacitor CLI는 `webDir`을 프로젝트 루트(`.`)로 지정하는 것을 허용하지 않고, `node_modules`/`.git`까지 통째로 안드로이드 assets에 복사되는 것을 막기 위해 `npm run build`(`scripts/build-www.js`)가 필요한 런타임 파일만 `www/`에 모아줍니다.
5. **에뮬레이터/기기에 Google 계정이 없을 때**
   - Google 로그인 시 "기기에 로그인된 Google 계정이 없습니다"라는 메시지가 뜨면, 기기 설정 > 계정에서 Google 계정을 추가한 뒤 다시 시도해주세요. (에뮬레이터는 기본적으로 Google 계정이 없는 상태로 생성됩니다.)

# 알림 기능 (안드로이드 앱 전용)

토스 등 은행 앱과 직접 연동하지 않고도, 이미 앱에 등록해둔 "반복 수입/고정 지출" 데이터만으로 아래 알림을 자동으로 예약합니다. **웹/PWA에서는 동작하지 않고, 안드로이드 앱에서만 동작**하도록 범위를 좁혔습니다.

## 어떤 알림이 오나요
- 반복 지출(고정 지출/자동결제) 예정일 3일 전, 2일 전, 1일 전에 각각 알림: "OO일 후 자동결제 예정 · 넷플릭스 · 14,500원"
- 반복 수입(용돈 등) 입금 예정일도 동일하게 D-3/D-2/D-1 알림
- 이번 달 사용 가능 금액을 매일 아침 9시에 한 번 알림 (앱을 마지막으로 연 시점 기준으로 계산됩니다)

## 켜고 끄기
설정 > "결제·입금 알림" 스위치로 켜고 끌 수 있습니다 (안드로이드 앱에서만 이 항목이 보입니다). 반복 항목을 추가/수정/삭제하거나 앱을 열 때마다 알림이 최신 데이터로 자동 재예약됩니다.

## 적용 방법 (필수)
코드만 바꿔서는 기기에 반영되지 않습니다. 아래 순서로 실제 안드로이드 앱에 반영해주세요.

```bash
npm install
npm run build
npx cap sync android
```

이후 Android Studio에서 다시 빌드/실행합니다. 처음 실행 시 안드로이드가 알림 권한을 물어보면 허용해주세요 (안드로이드 13 이상에서는 필수입니다).

## 알아둘 점 (로컬 알림의 한계)
- 서버 없이 기기에서만 예약하는 방식이라, "이번 달 사용 가능 금액" 알림은 마지막으로 앱을 연 시점의 값을 기준으로 미리 예약해둔 것입니다. 며칠 동안 앱을 전혀 열지 않으면 그 사이 금액 변화가 반영되지 않을 수 있습니다.
- 기기 제조사의 배터리 최적화 기능이 강하게 걸려 있으면(특히 삼성/샤오미 등 일부 기기) 예약된 알림이 늦게 오거나 오지 않을 수 있습니다. 이 경우 설정에서 이 앱을 배터리 최적화 제외 대상으로 추가하는 것이 좋습니다.

# 은행/카드 자동 연동에 대하여 (토스 등)

토스를 비롯한 국내 은행/카드 앱은 개인이 바로 붙일 수 있는 공식 API를 제공하지 않습니다. 계좌/카드 데이터를 자동으로 가져오려면 오픈뱅킹(금융결제원) 또는 마이데이터 사업자로 등록해야 하는데, 이는 법인 등록과 금융보안 심사가 필요한 영역이라 개인 프로젝트로는 진행할 수 없습니다. 로그인 정보를 앱에 직접 넣어 자동으로 값을 가져오는 방식(스크래핑)은 토스 이용약관 위반이자 보안 위험이 커서 권장하지 않습니다.

대신 아래 두 가지로 "수동 입력을 최소화"하는 방향을 제안합니다.

## 1) 반복 항목 기반 알림 (적용 완료)
이미 등록한 반복 수입/지출 데이터로 결제/입금 예정을 미리 알려주는 기능을 위 섹션과 같이 추가했습니다. 한 번 등록해두면 이후로는 손댈 필요가 없습니다.

## 2) 결제 알림 문구 자동 인식 (다음 단계 제안, 이번엔 구현하지 않음)
안드로이드에는 다른 앱에서 오는 알림(예: 카드사 결제 알림, 은행 입출금 알림)의 내용을 읽을 수 있는 `NotificationListenerService`라는 기능이 있습니다. 뱅크샐러드, 브로콜리 같은 가계부 앱들이 실제로 이 방식을 씁니다. 이 프로젝트에 적용하려면 아래 작업이 추가로 필요합니다.

- Capacitor용 커스텀 네이티브 플러그인 제작 (Kotlin/Java로 `NotificationListenerService` 구현)
- 안드로이드 설정에서 "알림 접근 권한"을 사용자가 직접 허용해야 함 (앱 안에서 자동으로 켤 수 없고, 시스템 설정 화면으로 이동해서 수동으로 허용해야 하는 권한)
- 은행/카드사별로 알림 문구 형식이 제각각이라(예: "OO카드 승인 12,000원 스타벅스" vs "[Web발신] 하나은행 입금 50,000원") 카드사·은행별 정규식 파싱 규칙을 하나씩 만들고 테스트해야 함
- 중복 등록 방지(같은 결제가 알림 두 번 오는 경우 등), 오작동 시 잘못된 금액이 등록되는 문제에 대한 검증 로직 필요

작업량이 크고, 실제 기기에서 여러 은행 알림 문구로 테스트해봐야 완성도가 나오는 기능이라 이번 작업에는 포함하지 않았습니다. 원하시면 다음 단계로 진행할 수 있습니다.

# 개선 제안 (다음에 고려해볼 것들)

현재 앱은 달력 기반 수입/지출 관리, 카테고리, 예산(배분형+월목표형), 반복 항목, 통계, 다크모드, Firebase 동기화, PWA/Android까지 개인 가계부에 필요한 핵심 기능을 대부분 갖추고 있습니다. 아래는 기능을 더 다듬거나 다른 가계부 앱과 차별화할 수 있는 아이디어입니다.

## 기능 개선 아이디어
- 전체 내역 검색/필터: 현재는 선택한 날짜의 내역만 보이므로, 메모나 카테고리로 전체 내역을 검색하는 화면이 있으면 특정 지출을 찾기 편해집니다.
- CSV 내보내기: 백업용 JSON 외에 엑셀에서 바로 열 수 있는 CSV 내보내기를 추가하면 가계부 데이터를 다른 곳에서 분석하기 쉬워집니다.
- 반복 항목 일시 중지/건너뛰기: 이번 달만 반복 지출을 제외하고 싶은 경우(예: 구독 해지 예정)를 위한 "이번 회차 건너뛰기" 기능.
- 예산 초과 알림: 월 예산 카테고리가 일정 비율(예: 80%, 100%)을 넘으면 배지나 알림으로 알려주는 기능.
- 자산/계좌 잔액 관리: 지금은 수입-지출 흐름만 추적하므로, 통장/카드/현금 등 실제 계좌 잔액을 함께 관리하면 "가계부"에서 "자산 관리"로 확장할 수 있습니다.
- 삭제 취소(휴지통): 실수로 삭제한 내역을 잠시 복구할 수 있는 임시 보관 기능.
- 오프라인 동기화 충돌 처리: 여러 기기에서 동시에 오프라인으로 수정한 뒤 동기화하면 마지막 저장이 이전 내용을 덮어쓰므로, 충돌 시 병합하거나 경고하는 로직을 추가하면 더 안전합니다.

## 차별화 아이디어
- 잔액 기반 예산 나누기: "잔액 예산 나누기"(실제 잔액을 항목별로 배분)와 "월별 예산 목표"(카테고리별 지출 한도)를 둘 다 제공하는 구조는 단일 예산 방식만 지원하는 대부분의 가계부 앱과 다른 강점이므로, 온보딩 화면에서 이 차이를 명확히 설명하면 차별점이 부각됩니다.
- 예정 수입/지출 구분 표시: 반복 항목을 "예정"과 "실제"로 나눠 달력에 보여주는 방식은 이번 달 남은 계획을 미리 파악하는 데 유용한 차별점입니다. 이를 활용해 "이번 달 남은 예정 지출까지 반영한 예상 잔액" 카드를 추가하면 더 돋보일 수 있습니다.
- 개인화 테마: 다크모드 + 5가지 색상 테마는 이미 있으니, 카테고리별 색상/아이콘 지정까지 지원하면 달력과 내역 목록이 한눈에 더 잘 들어옵니다.
- 목표 저축 기능: 예산 나누기 기능을 확장해 "여행자금 300만원 모으기"처럼 목표 금액과 달성률을 보여주는 저축 목표 카드를 추가하면 단순 지출 관리 앱과 다르게 동기부여 요소를 제공할 수 있습니다.
